## construction

- keep stock Codex as the executable and preserve native context and permission
  handling. do not introduce a model switch, launcher replacement, transcript
  rewrite, automatic Git commit, or cloud call in a native hook.
- keep the Rust task store authoritative for plan, revision, generation, cursor,
  and receipts. Python work and typed decisions use that task identity. one
  canonical store owns each fact.
- assemble a whole layer before its integrated proof. use syntax, type, and
  build smoke during construction. run the joined proof once for the candidate,
  group real failures by cause, and rerun affected checks after repair.
- reuse an unchanged passing receipt. keep failed and unknown outcomes distinct.
  generated reports and logs are outputs; they do not invalidate source proof.
- preserve one operation owner for a physical keyboard, pointer, page workflow,
  or phone. require a fresh observation before input and an app-owned readback
  for claims of completion.

## boundaries

do not add private logs, raw conversations, local device IDs, account details,
provider credentials, or host-specific paths to this public repository. do not
load a dotenv file for a provider call. hooks do local work; semantic calls run
only as explicit foreground operations. a backend or browser subprocess must
not inherit provider secrets.

native hook coverage is limited to supported event and tool shapes. code-mode
nested calls use those events. do not block an entire tool transport to catch a
single command. keep deterministic rules for permission, source generation,
exact values, and proof. typed scores advise bounded choices.

## release

record the exact build, inputs, result, and artifacts for each gate. distinguish
source checks, installation, live application behavior, and publication. publish
through the existing authorized route only after the agreed gates pass. retain
rollback and stop after the requested result is verified.
